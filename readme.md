## 🐱 What Is This?

This is a **Vial-enabled fork** of [holykeebs/qmk_firmware](https://github.com/idank/qmk_firmware), the QMK-based firmware with excellent support for pointing devices (trackballs, touchpads, trackpoints).

The upstream holykeebs repo runs on an older QMK base that predates Vial support. This fork bridges that gap:

- 🎛️ **Vial** — configure your layout, layers, macros, and pointing device settings *live* without reflashing
- 🖱️ **All holykeebs pointing devices** — every driver, fully preserved
- 📦 **Pre-built `.uf2` files** — grab a firmware from [Releases](https://github.com/alliecatowo/allie-cat-keeb-vial/releases) and go

---

## ✨ Why This Fork?

> **tl;dr** — holykeebs hardware is great, but the firmware doesn't support Vial. This fixes that.

| Problem | This Fork's Solution |
|---------|---------------------|
| Holykeebs ships an older QMK base with no Vial | Backported Vial's quantum layer + keycode protocol |
| Can't adjust pointing device sensitivity without reflashing | Full Vial GUI support — change anything live |
| No pre-built firmwares for common device combos | GitHub Releases with all `.uf2` variants built in CI |
| Tedious to track upstream changes manually | Daily automated sync PRs from holykeebs, Vial, and QMK |
| No shared userspace for personal config | `users/alliecatowo` with OLED logofont, RGB, and debug helpers |

## 📦 Quick Start — Flash Pre-built Firmware

Don't want to build from source? That's totally valid. 🙂

1. Head to the [**Releases page**](https://github.com/alliecatowo/allie-cat-keeb-vial/releases)
2. Download the `.uf2` for your config:

   ```
   lily58_rev1_vial_trackball_tps43_left.uf2
   lily58_rev1_vial_trackball_tps43_right.uf2
   ```

3. Enter bootloader mode on each half: **double-tap the RESET button**
4. An `RPI-RP2` USB drive appears — drag-and-drop the `.uf2` onto it
5. Repeat for the other half with its respective `.uf2`

### Firmware naming convention

```
{keyboard}_{keymap}_{left_device}_{right_device}_{side}.uf2
```

## 🛠️ Build From Source

### Prerequisites

```bash
# macOS (recommended)
brew install qmk/qmk/qmk

# Linux / WSL
sudo apt-get install -y git python3-pip
pip3 install qmk
qmk setup -y
```

> ⚠️ **Build from this fork**, not from the base QMK or holykeebs repo — this fork has the Vial patches applied.

### Clone & build

```bash
git clone --recurse-submodules https://github.com/alliecatowo/allie-cat-keeb-vial.git
cd allie-cat-keeb-vial

# Set up environment
export ORIG_CWD="$PWD" QMK_HOME="$PWD" QMK_FIRMWARE="$PWD"
export PYTHONPATH="$PWD/lib/python" PATH="$PWD/bin:$PATH"

# Build the default config (lily58, trackball left + TPS43 right)
python3 build.py
```

### `build.py` options

```bash
# Build Allie's personal config (lily58/rev1, trackball + TPS43, both sides)
python3 build.py --build-personal

# Build a specific variant
python3 build.py --build-single \
  --keyboard lily58/rev1 \
  --keymap vial \
  --left-device trackball \
  --right-device tps43 \
  --side left

# Build all release variants
python3 build.py --build-all

# Preview the CI release matrix (no build)
python3 build.py --generate-matrix-release
```

### Direct `make` command

```bash
make lily58/rev1:via \
  -e USER_NAME=holykeebs \
  -e POINTING_DEVICE=trackball_tps43 \
  -e SIDE=left \
  -e TRACKBALL_RGB_RAINBOW=yes \
  -e VIAL_ENABLE=yes
```

### Quick validation (no ARM toolchain required)

```bash
# Set up environment
export ORIG_CWD="$PWD" QMK_HOME="$PWD" QMK_FIRMWARE="$PWD"
export PYTHONPATH="$PWD/lib/python" PATH="$PWD/bin:$PATH"

python3 -m pip install -r requirements-dev.txt

# Run unit tests (~5 seconds)
python3 -m unittest tests.test_build_py -v

# Lint Python
flake8 build.py tools/callgraph.py --max-line-length=120
```

## 🔄 GitHub Actions in Your Fork

Fork the repo and you get a full automation suite for free!

### Workflows at a glance

| Workflow | Trigger | What it does |
|----------|---------|-------------|
| 🏗️ **Build Firmware** | `v*` tag push | Builds all `.uf2` variants and creates a GitHub Release |
| ✅ **Quick Tests** | Push / PR to `main` | Runs Python unit tests and linting |
| 🔍 **PR Checks** | Pull requests | Validates PR description, builds firmware, checks labels |
| 🤖 **PR Assistant** | Pull requests | Auto-labels PRs based on changed files |
| 🔄 **Sync Upstreams** | Daily 2 AM UTC | Opens PRs to pull changes from holykeebs, Vial, and QMK |
| 📝 **Changelog** | Releases | Auto-generates changelog from conventional commits |
| 📋 **Release Drafter** | Pushes to `main` | Drafts release notes from PR titles and commit history |
| 🤖 **Copilot Setup** | Codespaces / Copilot | Bootstraps the Copilot coding-agent environment |

### Setup

1. Go to your fork → **Settings → Actions → Enable Actions**
2. Pushes to `main` or PRs run the quick-tests and PR checks workflows
3. Pushing a `v*` tag triggers a full firmware build + GitHub Release

### Cut a release

```bash
git tag v1.2.0
git push origin v1.2.0
```

The workflow will:
- Build all `.uf2` firmware variants
- Create a GitHub release draft
- Attach all firmware files as assets
- Auto-generate a changelog

## 🔧 What Changed vs Upstream

This fork layers three things on top of [holykeebs/qmk_firmware](https://github.com/idank/qmk_firmware):

### 1. Vial core integration
- Backported Vial's quantum layer from [vial-qmk](https://github.com/vial-kb/vial-qmk)
- Added Vial keycodes, config structures, and communication protocol
- Added `.vil` keyboard definition files

### 2. Build system
- `build.py` — Python script that drives the full CI/release matrix
- Vial-specific build flags and memory optimizations for RP2040
- GitHub Actions workflows for builds, tests, changelog, and upstream sync

### 3. Memory optimizations
- Carefully balanced feature flags to fit Vial overhead within RP2040 flash constraints
- All holykeebs pointing device features preserved

### 4. Personal userspace (`users/alliecatowo`)
- Shared keymap helpers, OLED customization with a **custom hand-crafted pixel logofont**, RGB config, and debug utilities
- EEPROM layout config (`eeprom_config.h`) for persistent pointing-device settings
- RPC helpers (`rpc.c` / `rpc.h`) for split-keyboard communication
- Lives alongside the keyboard-specific keymaps for easy reuse across boards

## 🚨 Troubleshooting

<details>
<summary><strong>🔌 Vial doesn't detect my keyboard</strong></summary>

- Make sure you flashed the **Vial-enabled** firmware from this fork's releases (not upstream holykeebs)
- Try a different USB cable or port
- For split keyboards: both halves need to be flashed
</details>

<details>
<summary><strong>🖱️ Pointing device not working</strong></summary>

- Double-check you downloaded the right firmware variant for your hardware combo
- Verify wiring — see [docs.holykeebs.com](https://docs.holykeebs.com)
- Flash the debug build and open a serial console for logs
</details>

<details>
<summary><strong>🔨 Build fails</strong></summary>

- Ensure you're building **from this fork** (not base QMK)
- Set the required env vars: `export ORIG_CWD="$PWD" QMK_HOME="$PWD" QMK_FIRMWARE="$PWD" PYTHONPATH="$PWD/lib/python" PATH="$PWD/bin:$PATH"`
- Run `qmk doctor` to validate your environment
- Initialize submodules: `git submodule update --init --recursive`
- Check `python3 -m unittest tests.test_build_py -v` for logic errors
</details>

<details>
<summary><strong>🤖 Using with Codex / Copilot coding agents</strong></summary>

See [AGENTS.md](AGENTS.md) for environment bootstrap steps — the env vars above must be set before any tool calls or sub-agent invocations.
</details>
